# CmdBox

终端里的命令小抄。按 `Ctrl+G` 弹出来，敲几个字母就把常用命令筛到眼前，`Tab` 填进命令行，确认没问题再回车。

不用背 `git commit --amend --no-edit` 这种长命令，也不用在历史记录里翻半天。

## 目录结构

根目录这 11 样东西：

    main.cpp              程序本体。所有 .h/.cpp 都在这个文件里被 include 进来
    Makefile              编译脚本。一条 make 出二进制，不用背那串 g++ 参数
    README.md             这份说明
    LICENSE               MIT 许可证
    data.txt              命令库。一行一条，格式 id|命令|说明|标签
    ai脚本/               bash 集成。一个 cmdbox.bash，把 Ctrl+G 绑到这个程序上
    database/             数据层。链表、前缀树、文件读写、默认数据
    backend/              逻辑层。全文搜索（KMP）、冒号命令（:add :del :edit …）
    frontend/             界面层。终端原始模式、按键解析、画屏
    网页介绍.html         交互式导图。用浏览器打开，点节点看代码
    下一版本升级内容.txt  待办清单。下一版要修的 7 个问题

`database/`、`backend/`、`frontend/` 三个目录内部都是 `include/` 放 `.h`、`src/` 放 `.cpp`。

`main.cpp` 里把所有 `.h` 和 `.cpp` 都 `#include` 进来了，看着像写错，但这是故意的：整个项目只有一个编译单元，省掉链接那一步。别把它"修"成标准的多文件编译。

分三个目录是为了分层：`database` 管数据，`backend` 管逻辑，`frontend` 管终端。按键、搜索、存储互不牵扯。

## 装它，就三步

**第一步：下载**

打开这个仓库，点右上角绿色的 `Code` 按钮，选 `Download ZIP`；会用 git 的话直接 `git clone` 也行。解压后你会得到一个文件夹。

**第二步：进文件夹，编译**

打开终端，用 `cd` 进到你刚解压出来的那个文件夹。里面应该能看见 `main.cpp` 和 `Makefile` 两个文件——有就是进对了。

然后运行：

    make

几秒钟后，文件夹里多出一个叫 `cmdbox` 的可执行文件。

如果报 `g++: 未找到命令`，先装编译器：`sudo apt install g++`。

**第三步：让它接管 Ctrl+G**

用任意编辑器打开 `~/.bashrc`（比如 `nano ~/.bashrc`），拉到最下面，加一行：

    [ -f "$HOME/cmdbox/ai脚本/cmdbox.bash" ] && source "$HOME/cmdbox/ai脚本/cmdbox.bash"

把里面的 `$HOME/cmdbox` 换成你实际放这个文件夹的位置。

保存，关掉终端重新打开（或者执行 `source ~/.bashrc`）。

现在随便敲几个字，按 `Ctrl+G`。

## 按下去之后

屏幕会清空，弹出一个列表：

    CmdBox ↑↓ 选择  Tab补全命令  Enter搜索  Ctrl+C退出
    数据文件:/home/你/cmdbox/data.txt

    > git
    > git add -A  # 暂存所有改动  [git] id:1
      git commit -m "fix"  # 提交并写明本次修复内容  [git] id:2
      git push  # 把本地提交推送到远程仓库  [git] id:3

- 敲 `git`，列表立刻只剩命令**开头是 git** 的几条
- `↑` `↓` 选，`Tab` 把选中的命令填进你正在写的那一行
- 填进去**不会自动执行**，你还能改，改完自己按回车
- `Ctrl+C` 放弃，命令行一个字都不动

## 快捷键

| 按键 | 作用 |
|---|---|
| 字母 / 数字 | 追加到搜索串，按**命令开头**重新筛选 |
| `↑` `↓` | 上下移动选中项 |
| `Tab` | 把选中那条命令填进命令行 |
| `Backspace` | 删掉搜索串最后一个字符（中文按整字删） |
| `Enter` | 搜索串不是 `:` 开头 → 全文搜索；是 `:` 开头 → 执行命令 |
| `Ctrl+C` | 退出，什么都不改 |

## 冒号命令

在输入框里敲 `:命令` 再回车：

| 命令 | 作用 |
|---|---|
| `:list` | 列出全部命令 |
| `:add` | 添加一条（依次问：命令 → 说明 → 标签） |
| `:edit 编号` | 修改第 N 条 |
| `:del 编号` | 删除第 N 条 |
| `:quit` | 退出 |

添加时会连问三行，比如：

    命令: git log --oneline -10
    说明（可留空）: 看最近十条提交
    标签（默认 misc）: git

三个字段都不能包含 `|`，那是文件里的分隔符。

## 数据文件

`data.txt` 就在可执行文件旁边，一行一条，四个字段用 `|` 隔开：

    id|命令|说明|标签

示例：

    1|git add -A|暂存所有改动|git
    2|git commit -m "fix"|提交并写明本次修复内容|git
    3|ls -la|列出所有文件（含隐藏文件）|linux

用记事本直接改也行，程序每次启动重新读一遍。保存时是"先写临时文件再改名"，中途断电不会把原文件写坏。

**注意**：程序是靠自己的位置去找 `data.txt` 的。你把 `cmdbox` 挪到别的目录，那边就会当成空库，`data.txt` 也记得一起搬。

## 已知问题

- **只支持 Linux**。用了 termios、`/dev/tty`、`/proc/self/exe`，Windows 和 macOS 跑不了。
- **窗口太窄会折行**。主界面固定占 10 行，长命令超出宽度就折到下一行，把下面的内容顶乱。
- **单按 ESC 会假死**。读键时按了 ESC 之后还会再等一个字节判断方向键，你只按 ESC 它就一直等。
- **候选项按首字节排序**，不是按编号。所以列表里编号可能是 4 1 2 3 这种顺序。
- **`:add` 状态下按 Ctrl+C 会杀掉整个进程**。那时候终端处于正常模式，Ctrl+C 被系统当成中断信号。
- **用 `-O2` 编译会报一条 `readlink` 返回值未检查的警告**，不影响运行。
